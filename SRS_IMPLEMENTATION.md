# SRS implementation map

| SRS requirement | Implementation |
|---|---|
| Support 10th, 12th, Bachelor's, Master's | API validation, stage-specific feature contracts and separate saved models; 10th results are stream/pathway choices. |
| Education-specific academic inputs | `/api/education/catalog`, `backend/education_catalog.py`, normalized education catalog tables, and assessment UI; 10th/12th streams and degree/specialization-specific Bachelor’s/Master’s subjects, custom subject entry, degree, specialization, year/semester, marks, research interests, and career/education preferences persist with student profile. Preference matches contribute to knowledge compatibility. |
| Actual aptitude assessment | `backend/aptitude_bank.py`, question/attempt APIs, and normalized attempt/answer/domain-score tables; 25 MCQs across seven domains, randomized per attempt, key/explanation hidden until submission, backend scoring only, history and retake. Legacy slider-score writes are rejected. |
| Separate interests and skills | Interests, technical skills and employability skills remain distinct assessment types; UI explains interest vs self-assessed proficiency scales. |
| Hybrid recommendations | `backend/services/recommendation_engine.py` combines career knowledge/profile compatibility (90%) with the stage-specific trained family probability (10%), orders results by that score, computes skill gaps, and builds personalized actions. Synthetic model evidence is labeled experimental. |
| Skill gaps and personalized roadmap | Requirement minus observed score per career/pathway, severity bands and gap-specific action lists. Missing ratings are unknown. Class 10 results add an education-catalog and maintained-career-record roadmap with four progression stages, prerequisites to verify, skill exploration, and counselor/teacher conversations. Local eligibility is explicitly not inferred. |
| RF and XGBoost, test split/CV and metrics | `backend/ml/train_career_models.py`; per-stage stratified 80/20 holdout plus 5-fold CV, class reports, confusion matrices and saved JSON metrics. |
| Kaggle + synthetic data provenance | `DATA_SOURCES.md`; local four-stage career models remain on generated synthetic profiles. A separate 50,000-row Kaggle synthetic university benchmark compares RF/XGBoost and records its lower test accuracy; no Kaggle records are represented as real students. |
| Explainability | SHAP TreeExplainer for saved tree models; SHAP feature contributions and compatibility-component reasons are returned with recommendations when supported. |
| Provenance separation | UCI public data in `data/raw/`, synthetic records under `data/synthetic/`, derived metrics in `data/processed/`, runtime questionnaire data in the application database; provenance in `DATA_SOURCES.md`. No user survey cohort was supplied. |
| Preserve originals | Generators write to separate synthetic/processed locations and do not touch UCI raw archive files. No CareerPath.ipynb was edited. |
| Admin features and role-based access | Bootstrap admin through `.env`; protected dashboard, user/profile detail, account enable/disable and role management, career create/edit/deactivate, skill catalog, aptitude question administration, dataset provenance inventory, recommendation/system statistics, model comparisons/baselines, API errors and audit log. |
| Authenticated header and session | Navigation displays backend-returned email, account link, logout menu; bearer token is kept in sessionStorage, revalidated through `/api/auth/me` on reload, and revoked by `/api/auth/logout`. Admin endpoints enforce roles on the server. |
| MySQL and normalized schema | MySQL URL from `.env`, scoped DB account instructions, foreign keys; student marks, assessment dimensions, aptitude attempts/responses/domain scores, career streams, subjects, requirements, skills and pathways use relational rows. The additive migration preserves existing application records. SQLite is the local/test adapter. |
| Flask REST + React/Vite | `backend/app.py`; `frontend/src/main.jsx`; API contract in `API_DOCUMENTATION.md`. |
| Modular ML | Separate loader, stage feature contract, preprocessing/training, evaluation metrics, predictor, SHAP explanation, recommendation and skill-gap modules. |
| Reproducibility | Fixed seeds, generated synthetic source, saved joblib pipelines, `requirements.txt`, documented commands and stored evaluation JSON including a separate majority-class baseline report. |
| Independent backend/data/ML validation | Added API coverage for stage catalog, profile degree metadata, hidden answer key, authenticated attempt creation, complete-answer scoring, result/history persistence, and duplicate submission rejection. |
| Frontend build/integration | Vite production build and regression suite are rerun after the changes. |

## Validation scope and limitations

The supplied UCI data is used for the academic grade-band experiment only. Career family models use synthetic generator-labeled records, so their held-out/CV scores evaluate consistency with synthetic assumptions rather than real-world career outcomes. No real-student survey data was available. The configured MySQL endpoint could not be reached from this implementation environment, so no live MySQL migration or integration test was run. Run the API tests against the configured MySQL service before deployment; isolated SQLite integration tests cover the backend request flows.

Admin edits to career descriptions and skill requirements are written to the project knowledge-base CSV, which the recommendation service reloads for each request. Student profiles, normalized assessments and stored recommendation results are persisted through the configured database. Assessment recommendations use the most recent backend-scored aptitude attempt for authenticated students. Real MySQL hosting still requires applying the additive migration and validating with the target MySQL server and app account.
